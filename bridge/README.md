# CyberFinger Bridge

GUI application that connects CyberFinger BLE controllers to your PC
in several modes:

- **VR Mode** — fuses controller buttons, the runtime hand skeleton and 6DOF hand
  poses into the CyberFinger SteamVR driver's virtual controllers
- **Gamepad Mode** — combines left + right controllers into a virtual Xbox 360
  gamepad (Resonite and VRChat variants)

Independently of the mode, it can also emulate **SlimeVR trackers** from the
controller IMUs, and it visualises hand state, IMU orientation and the tracked hand
skeleton.

## Quick Start (from source)

```
pip install -r requirements.txt
python cyberfinger_gui.py
```

`openvr` (pyopenvr) is required for the hand skeleton, 6DOF and VR fusion; the
gamepad modes work without it.

## Settings

Stored in `%APPDATA%\CyberFingerBridge\settings.json`, written by the GUI.
A few options have no UI:

| Key | Default | Description |
|-----|---------|-------------|
| `slimevr_host` / `slimevr_port` | `127.0.0.1` / `6969` | SlimeVR server address |
| `skeleton_enabled` | `true` | Set false to disable the skeleton client entirely |
| `skeleton_backend` | `"auto"` | `"openvr"` / `"openxr"`; auto picks OpenXR only on Monado/WiVRn, so Windows always resolves to OpenVR |
| `skeleton_bisect` | `false` | Bring the OpenVR session up in logged stages (debugging) |

## Testing

```
python test_slimevr.py
```

Standalone — no hardware, no SteamVR. Checks the BLE report parsing (including
the 79-byte IMU+accel report and its older prefixes), gravity removal, the
SlimeVR protocol against a mock server, the skeleton action manifest, and the
driver packet layouts.

> **Note:** this file is not tracked in the repo. Everything it exercises now
> lives in `../bridge_common/` rather than in `cyberfinger_gui.py`, so import
> from there instead — `parse_report`/`linear_accel_ms2` from
> `bridge_common.protocol`, the tracker from `bridge_common.slimevr`, the packet
> layouts from `bridge_common.vr_controller`. Being shared by both bridges, that
> code is now the natural place for these tests to live.

## Building the Installer

### Prerequisites

1. Install build dependencies:
   ```
   pip install pyinstaller pillow
   pip install -r requirements.txt
   ```

2. Install [Inno Setup 6](https://jrsoftware.org/isdl.php) (for creating the installer)

3. (Optional) Download [ViGEmBus driver installer](https://github.com/nefarius/ViGEmBus/releases)
   and place it as `installer/ViGEmBus_Setup.exe` — the installer will offer to
   install it automatically for Gamepad mode users.

### Build Steps

```
build.bat
```

This will:
1. Convert the PNG icon to ICO format
2. Run PyInstaller to create `dist/CyberFingerBridge.exe`
3. Prepare the distribution files

To create the Windows installer:
```
cd installer
iscc setup.iss
```

The installer will be created at `dist/installer/CyberFingerBridge_Setup_1.0.0.exe`.

## Project Structure

```
cyberfinger_gui.py          Main GUI (WinRT BLE, ViGEm gamepad modes, app shell)
cyberfinger_bridge.py       Headless CLI bridge (buttons only, no skeleton)
cyberfinger_bridge.spec     PyInstaller build spec
build.bat                   Build script
requirements.txt            Python dependencies
assets/
  icon.png                  App icon (200x196 PNG)
  icon.ico                  App icon (generated by build)
  icon_32x32*.png           Tray icons
installer/
  setup.iss                 Inno Setup installer script
  ViGEmBus_Setup.exe        (user-provided) ViGEmBus driver installer
```

Everything above the platform transports is shared with the Linux bridge in
`../bridge_common/`, so the two cannot drift apart:

```
../bridge_common/
  protocol.py               GATT wire format, IMU report decoding, HandState
  slimevr.py                SlimeVR tracker emulation
  skeleton.py               OpenVR hand-skeleton + 6DOF client (SteamVR)
  skeleton_openxr.py        Native OpenXR headless hand tracking (Monado/WiVRn)
  vr_controller.py          FusedVRMode — HTSK/CFGP driver stream
  panels.py                 Hand + skeleton visualisation canvases
  graphics.py               Palette and 3D maths
  platform.py               The only OS branch: config dir, SteamVR path, font
  assets/
    cyberfinger_actions.json     OpenVR action manifest (hand skeleton)
    cyberfinger_bindings_*.json  Default bindings per controller type
```

What stays in `bridge/` is genuinely Windows-specific: BLE over WinRT, the
ViGEm virtual gamepad, tray icon loading and the app shell.

> **Packaging note:** `bridge_common/assets/*.json` are located at runtime via
> `bridge_common.platform.shared_asset()`, which checks the frozen bundle's flat
> `assets` directory first. They are listed individually in `datas` in
> `cyberfinger_bridge.spec`, which also puts the repo root on `pathex` so
> `bridge_common` is importable at build time. Add any new binding file to
> `datas` too, or the hand skeleton will silently fail to bind in the frozen
> build.

> **sys.path note:** both GUIs *append* the repo root rather than inserting it.
> The repo root contains the OpenVR SDK's `openvr/` directory, which ahead of
> site-packages would import as an empty namespace package and shadow pyopenvr.

## Gamepad Button Mapping

| Bit  | Button       | Right Hand             | Left Hand              | XInput btn # |
|------|--------------|------------------------|------------------------|--------------|
| 0x01 | Trigger      | A                      | X                      | 1 / 3        |
| 0x02 | Grip         | B                      | Y                      | 2 / 4        |
| 0x20 | Menu         | RB (R-Shoulder)        | LB (L-Shoulder)        | 6 / 5        |
| 0x40 | Joy Click    | R3 (R-Thumb)           | L3 (L-Thumb)           | 10 / 9       |
| 0x80 | Start/Select | Start                  | Back                   | 8 / 7        |
| 0x04 | C            | btn 11 (D-pad Up raw)  | btn 14 (D-pad Right raw) | 11 / 14    |
| 0x08 | D            | btn 12 (D-pad Down raw)| btn 15 (Guide raw)     | 12 / 15      |
| 0x10 | E            | btn 13 (D-pad Left raw)| btn 16 (reserved raw)  | 13 / 16      |
| —    | Joystick     | Right Stick (Y inv)    | Left Stick (Y inv)     | —            |
| —    | Trigger analog | Right Trigger        | Left Trigger           | —            |

> **Note on buttons 11–16:** The Xbox 360 `wButtons` field has unused/reserved bits
> that ViGEm passes through to DirectInput as extra buttons. C/D/E are mapped there
> directly via `gp.report.wButtons` since they have no named `XUSB_BUTTON` enum entry.
